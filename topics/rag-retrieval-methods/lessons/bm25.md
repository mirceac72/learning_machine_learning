BM25 is a ranking function for term-based retrieval. It requires no training data, no learned parameters beyond two scalars, and no accelerator, yet it remains competitive with neural retrievers on many corpora and is the default first stage in most production search systems. ## Preliminaries

The derivation in Part I uses the following and nothing beyond it.

**Multisets.** A *multiset* is a collection in which an element may appear more than once and in which order is irrelevant. Writing $\{a, a, b\}$ denotes the multiset containing $a$ twice and $b$ once; it differs from the set $\{a, b\}$ but not from $\{a, b, a\}$. A document, for the purposes of this lesson, is a multiset of terms: repetition matters, position does not.

**Tokenisers.** A **tokeniser** is a function

$$\mathrm{tok} : \text{string} \longrightarrow \text{multiset of terms}$$

It is the only bridge between raw text and everything the scoring function operates on: after tokenisation there are no strings left in the model, only terms and their counts. Applied to `the cat sat on the mat`, whitespace splitting on lowercased text gives the multiset $\{\texttt{the}, \texttt{the}, \texttt{cat}, \texttt{sat}, \texttt{on}, \texttt{mat}\}$ — `the` twice, and no record of which word came first.

To be exact, a tokeniser as implemented emits an ordered *sequence* of terms; it is the model that then reads that sequence as a multiset, discarding the order but not the counts. The counts are kept because they carry evidence (§5, §7.1); the order is discarded because BM25 assumes terms are independent (§4.2, §4.6). The phrase and proximity extensions of §11 are the extensions that decline to throw the order away.

A tokeniser is a modelling decision rather than preprocessing. It fixes the vocabulary, and therefore fixes every document frequency, every term weight and every document length in the index (§1, §13).

**Conditional probability.** For events $A$ and $B$ with $P(B) > 0$,

$$P(A \mid B) \;=\; \frac{P(A \cap B)}{P(B)}$$

Rearranging gives $P(A \cap B) = P(A \mid B)\,P(B)$, and since $A \cap B = B \cap A$, also $P(A \cap B) = P(B \mid A)\, P(A)$. Equating the two and dividing by $P(B)$ yields **Bayes' theorem**:

$$P(A \mid B) \;=\; \frac{P(B \mid A)\, P(A)}{P(B)}$$

This is the only probabilistic identity the derivation requires. It is applied in §4.3, once to each of the two probabilities whose ratio is being ranked.

**The law of total probability.** If $A_1, \dots, A_m$ are mutually exclusive and exhaust all possibilities, then $P(B) = \sum_{i} P(B \mid A_i)\, P(A_i)$. It is used twice: in §4.3, to write the denominator of Bayes' theorem in a form that visibly cancels, and in §5, to write the distribution of a count as a mixture over a hidden variable.

**Independence.** Random variables $X_1, \dots, X_m$ are *mutually independent given* $C$ when $P(X_1, \dots, X_m \mid C) = \prod_i P(X_i \mid C)$. The assumption is introduced deliberately in §4.2 and is false; §4.6 records what it buys and what it costs.

**Bernoulli variables.** A variable taking only the values $0$ and $1$ has its distribution determined by the single number $p = P(X = 1)$, since $P(X = 0) = 1 - p$.

**Odds and logarithms.** For $p \in [0,1)$ the odds of $p$ are $p/(1-p)$. The natural logarithm $\ln$ is used throughout; $\log$ without a base denotes the same function. The two facts needed are that $\ln$ is strictly increasing on $(0,\infty)$, with derivative $1/x > 0$, and that it converts products to sums: $\ln(xy) = \ln x + \ln y$.

**Poisson distribution.** A count variable $F \in \{0, 1, 2, \dots\}$ is *Poisson with rate* $\lambda > 0$ when $P(F = f) = e^{-\lambda}\lambda^f / f!$. The only property used (§5) is that the ratio of two Poisson probabilities with different rates, $P_\lambda(f)/P_\mu(f) = e^{\mu - \lambda}(\lambda/\mu)^f$, is a geometric function of $f$.

**Maximum likelihood estimate.** Given observed data, the *maximum likelihood estimate* of a parameter is the value that makes the observed data most probable. For the probability of a binary event it is the observed proportion: $k$ successes in $n$ trials give $\hat{p} = k/n$. This is the only case used (§4.4).

**Asymptotic notation.** $O(f(n))$ denotes a quantity bounded above by a constant multiple of $f(n)$ for all sufficiently large $n$. It is used only in §12.2–§12.3 to state costs.

Two terms from computing rather than mathematics also appear, each explained where it is used: the *inverted index* (§3) and the *min-heap* (§12.2). One term from linear algebra, *cosine similarity*, appears in §11 and is defined there from the dot product.

## Part I — Theory

### 1. Problem statement

Retrieval is the following task. Given a query $q$ and a document collection $D$, compute a score $s(q, d)$ for each $d \in D$ and return the $k$ documents of highest score. The design space consists of two independent choices: the form of the scoring function, and the data structure that avoids evaluating it on the entire collection.

**Types.** The notation $q$ and $d$ suggests strings, but no scoring function operates on strings. Both are multisets of terms — multisets rather than sets because term counts carry information, and unordered because BM25 assumes term independence.

| Symbol | Mathematical type | Representation in code | Remarks |
|---|---|---|---|
| $q$ | multiset of terms | `list[str]` | order irrelevant; duplicates significant |
| $d$ | multiset of terms | `list[str]`, or `dict[str, int]` once counted | stored as counts in the index |
| $D$ | finite collection of documents | `list[list[str]]` at build time; inverted index at query time | never enumerated per query |
| $s(q, d)$ | function to $\mathbb{R}$ | `float` | unbounded; not a probability; comparable only within a single query |

Three consequences follow, each corresponding to a common implementation defect.

**(i) The tokeniser is part of the model.** Since $q$ and $d$ are outputs of tokenisation, $s$ is defined only relative to a tokeniser. Two systems sharing a scoring formula but differing in tokenisation are distinct retrievers. §13 treats this in detail.

**(ii) The collection has two representations.** At build time $D$ is a sequence of token lists, traversed once to compute document frequencies, inverse document frequencies, term counts and mean document length. At query time it is an *inverted index* — the structure defined in §3, which maps each term to the documents containing it. An implementation that iterates the build-time representation per query is correct and asymptotically wrong.

**(iii) Scores are not comparable across queries.** The magnitude of $s(q, d)$ depends on the number and rarity of terms in $q$. A score of 12.4 under one query and 8.1 under another carry no relative meaning. The same property holds between retrievers: a BM25 score and a similarity produced by some other method share no scale. This is why systems that combine two retrievers often combine their *ranks* rather than their scores (§11).

The following four-document collection is used throughout Part I. Tokenisation is whitespace splitting on lowercased text; no stopword removal (the dropping of function words such as `the`, `of`, `and`) or stemming is applied.


Derived quantities:

with $N = 4$ and $\mathrm{avgdl} = 29/4 = 7.25$.

### 3. The inverted index

The **inverted index** is a map, and the whole of term-based retrieval's efficiency follows from what its keys and values are.

- **The key is a term** — one element of the tokeniser's output vocabulary. The set of keys *is* the vocabulary of the collection: a term that is not a key occurs in no document, which is exactly the case §12 Step 8 discards from the query.
- **The value is the term's posting list** — the documents that contain it, each paired with the number of times it occurs there, held sorted by document identifier.

In types, `dict[term, list[tuple[doc_id, count]]]`.

The name records what has been reversed. A collection arrives in the *forward* direction, as a map from each document to the terms it contains; that direction answers the question "what is in this document". The index inverts it into a map from each term to the documents containing it, which answers "which documents contain this term" — and the second is the question scoring actually asks, since a query is a set of terms and the score of a document depends only on the query's terms.

For the running example:

```python
{
  "the":    [("d1", 2), ("d2", 3), ("d4", 2)],     # df = 3
  "cat":    [("d1", 1), ("d2", 1)],                 # df = 2
  "dog":    [("d2", 1), ("d4", 1)],                 # df = 2
  "sat":    [("d1", 1)],                            # df = 1
  "mat":    [("d1", 1)],                            # df = 1
  "chased": [("d2", 1)],
  "around": [("d2", 1)],
  "garden": [("d2", 1)],
  "dogs":   [("d3", 1)],                            # df = 1, distinct from "dog"
  "cats":   [("d3", 1)],
  "and":    [("d3", 1)],
  "are":    [("d3", 1)],
  "common": [("d3", 1)],
  "pets":   [("d3", 1)],
  "quick":  [("d4", 1)], "brown": [("d4", 1)], "fox":  [("d4", 1)],
  "jumps":  [("d4", 1)], "over":  [("d4", 1)], "lazy": [("d4", 1)],
}
```

**Why this structure and not another.** The shape of the index is dictated by the shape of the score. The scoring function derived in §4 is a sum over the query's terms alone, so evaluating it requires, for each query term, precisely the documents containing that term and the count in each — which is precisely one posting list. Four consequences follow, and together they are the reason term-based retrieval is fast.

- **The candidate set is a union of posting lists.** A document appearing in no posting list of any query term contains no query term, and therefore scores exactly zero. It need never be examined. Under the query `cat mat` the candidate set is $\{d_1, d_2\}$; $d_3$ and $d_4$ are never touched.
- **Query cost is decoupled from collection size.** What a query costs is governed by how long its terms' posting lists are, not by $N$. A rare term is cheap however large the collection, and this is the property that makes retrieval over $10^8$ documents feasible at all.
- **The index is closed with respect to the scoring function.** The count stored beside each identifier supplies $f(t,d)$; the length of the posting list supplies the document frequency $n_t$, hence the term's weight. With a separate array holding $\lvert d \rvert$ for each document, no quantity appearing in $s(q,d)$ requires anything outside the index — the raw text is never consulted again after `build`.
- **The sort by document identifier is load-bearing.** It permits the union above to be computed as a linear merge rather than by construction of an intermediate set, and it is a precondition for the skipping described in §10, which requires that documents be visited in a known order.

In production systems the posting lists are additionally compressed — identifiers are stored as differences between consecutive entries (*delta encoding*), which are small numbers because the list is sorted, and both are stored with variable-length integer codes; document-length norms are often quantised as well (§9). These details do not alter the ranking but account for the majority of an index's engineering complexity.

### 4. From the probability ranking principle to IDF

BM25 is not arbitrary — the algorithm has mathematical grounds, which are presented below. This section derives inverse document frequency from first principles. The derivation identifies which assumptions BM25 rests on, and therefore which of its failures are defects of implementation and which are consequences of the model.

#### 4.1 The probability ranking principle

**Notation.** Throughout this section $q$ denotes the query, a fixed multiset of terms as defined in §1. It is held constant: the entire derivation compares documents *under one query*, and every probability below is conditional on $q$. This is the formal reason for the observation in §1(iii) that scores are not comparable across queries — two queries induce two different conditional distributions, and there is no common scale between them.

The document $d$ ranges over the collection. Relevance is modelled as a binary random variable $R \in \{0, 1\}$, where $R = 1$ denotes that the user judges $d$ relevant to $q$. Relevance is a property of the pair, so the quantity of interest is the conditional probability $P(R = 1 \mid q, d)$.

**The principle.** The **probability ranking principle** (Robertson, 1977) states that, if documents are retrieved in decreasing order of $P(R = 1 \mid q, d)$, and if the utility of a retrieved set is additive over its members, then the resulting ranking is optimal with respect to expected utility. Retrieval is thereby reduced to the estimation of a conditional probability.

**Monotone invariance.** Estimating that probability directly is inconvenient. It is not necessary, because a ranking depends only on the *order* of the scores, not their values. If $\varphi$ is strictly increasing on the range of a scoring function $s$, then

$$s(q, d_1) > s(q, d_2) \iff \varphi\big(s(q,d_1)\big) > \varphi\big(s(q,d_2)\big)$$

so $s$ and $\varphi \circ s$ produce identical rankings. Any strictly increasing transformation may therefore be applied freely, and two are chosen because they simplify the algebra.

**Transformation 1: the odds.** For $p \in [0, 1)$, the **odds** of $p$ are defined as

$$\mathrm{odds}(p) \;=\; \frac{p}{1 - p}$$

This maps $[0,1)$ onto $[0, \infty)$ and is strictly increasing, since $\frac{d}{dp}\,\mathrm{odds}(p) = (1-p)^{-2} > 0$. Applying it to the quantity of interest, and writing $P(R = 0 \mid q, d) = 1 - P(R = 1 \mid q, d)$:

$$O(R \mid q, d) \;=\; \frac{P(R = 1 \mid q, d)}{P(R = 0 \mid q, d)}$$

Ranking by $O(R \mid q, d)$ is therefore equivalent to ranking by $P(R = 1 \mid q, d)$. The odds are chosen over any other increasing transformation because expressing the score as a ratio of two probabilities conditioned on the same evidence causes the intractable normalising constant to cancel when Bayes' theorem is applied in §4.3.

**Transformation 2: the logarithm.** The logarithm is strictly increasing on $(0, \infty)$ and so is likewise ranking-preserving. Its purpose emerges only in §4.3: once the independence assumption has turned the odds into a *product* over terms, the logarithm converts that product into a *sum*, which is the additive form that inverted-index retrieval requires.

#### 4.2 Document representation and the independence assumption

Two assumptions are now introduced.

**Assumption A1 (binary representation).** A document is represented by a binary incidence vector $\mathbf{x} = (x_1, \dots, x_V)$ over the vocabulary of size $V$, where $x_t = 1$ if term $t$ occurs in the document and $0$ otherwise. Term counts are discarded.

**Assumption A2 (conditional independence).** The components of $\mathbf{x}$ are mutually independent given relevance:

$$P(\mathbf{x} \mid R, q) \;=\; \prod_{t} P(x_t \mid R, q)$$

**Parameterisation.** Each component $x_t$ is a binary variable, so its conditional distribution is Bernoulli and is determined by a single number per relevance state. Define

$$p_t \;=\; P(x_t = 1 \mid R = 1, q), \qquad u_t \;=\; P(x_t = 1 \mid R = 0, q)$$

that is, the probability that term $t$ occurs in a relevant and in a non-relevant document respectively. Because $x_t$ takes only two values, the complementary cases are fixed by these:

| | $x_t = 1$ (term present) | $x_t = 0$ (term absent) |
|---|---|---|
| $R = 1$ | $p_t$ | $1 - p_t$ |
| $R = 0$ | $u_t$ | $1 - u_t$ |

The four entries are compactly written as a single expression in $x_t$, using the convention that an exponent of $0$ yields $1$:

$$P(x_t \mid R = 1, q) \;=\; p_t^{\,x_t}\,(1 - p_t)^{\,1 - x_t}, \qquad P(x_t \mid R = 0, q) \;=\; u_t^{\,x_t}\,(1 - u_t)^{\,1 - x_t}$$

Substituting $x_t = 1$ selects the first factor and reduces the second to $1$; substituting $x_t = 0$ does the reverse. Combining this with A2 gives the full likelihood of a document representation under each relevance state:

$$P(\mathbf{x} \mid R = 1, q) \;=\; \prod_{t} p_t^{\,x_t}\,(1 - p_t)^{\,1 - x_t}, \qquad P(\mathbf{x} \mid R = 0, q) \;=\; \prod_{t} u_t^{\,x_t}\,(1 - u_t)^{\,1 - x_t}$$

The model is thus fully specified by $2V$ parameters — one pair $(p_t, u_t)$ per vocabulary term — and this is the origin of the name **binary independence model**: binary because each $x_t \in \{0,1\}$, independent because the product in A2 factorises over terms.

The exponent notation is convenient for stating the model but is discarded immediately in §4.3, where the product is split according to whether $x_t$ equals $1$ or $0$ and each factor reduces to one of the four table entries above.

#### 4.3 Reduction to a sum of term weights

Since the document enters only through its representation, $O(R \mid q, d) = O(R \mid q, \mathbf{x})$. Bayes' theorem is applied separately to the numerator and the denominator of this quantity. Conditioning throughout on the fixed query $q$:

$$P(R = 1 \mid q, \mathbf{x}) \;=\; \frac{P(\mathbf{x} \mid R = 1, q)\, P(R = 1 \mid q)}{P(\mathbf{x} \mid q)}, \qquad P(R = 0 \mid q, \mathbf{x}) \;=\; \frac{P(\mathbf{x} \mid R = 0, q)\, P(R = 0 \mid q)}{P(\mathbf{x} \mid q)}$$

The denominator $P(\mathbf{x} \mid q)$ is the marginal probability of observing the representation $\mathbf{x}$ at all, obtained by summing the joint distribution over relevance:

$$P(\mathbf{x} \mid q) \;=\; \sum_{r \in \{0,1\}} P(\mathbf{x} \mid R = r, q)\, P(R = r \mid q)$$

It is a normalising constant, and it is the term that makes direct estimation of $P(R = 1 \mid q, \mathbf{x})$ impractical: computing it requires the very quantities being estimated. It does not depend on $R$, so it is identical in both expressions above, and forming their ratio eliminates it:

$$O(R \mid q, \mathbf{x}) \;=\; \frac{P(\mathbf{x} \mid R=1, q)\, P(R=1 \mid q) \,/\, P(\mathbf{x} \mid q)}{P(\mathbf{x} \mid R=0, q)\, P(R=0 \mid q) \,/\, P(\mathbf{x} \mid q)}$$

The factor $1/P(\mathbf{x} \mid q)$ appears once in the numerator and once in the denominator and divides out, leaving

$$O(R \mid q, \mathbf{x}) \;=\; \underbrace{\frac{P(R=1 \mid q)}{P(R=0 \mid q)}}_{\text{prior odds; independent of } d} \;\cdot\; \underbrace{\frac{P(\mathbf{x} \mid R=1, q)}{P(\mathbf{x} \mid R=0, q)}}_{\text{likelihood ratio}}$$

The result decomposes the score into a **prior odds** of relevance under the query and a **likelihood ratio** for the observed document representation. The first factor is the same for every document in the collection and therefore constant across the ranking; by the monotone invariance of §4.1 it may be discarded, leaving the likelihood ratio alone. Applying A2 to the second factor and separating the product according to whether the term is present:

$$\frac{P(\mathbf{x} \mid R=1, q)}{P(\mathbf{x} \mid R=0, q)} \;=\; \prod_{t\,:\,x_t=1} \frac{p_t}{u_t} \;\cdot\; \prod_{t\,:\,x_t=0} \frac{1-p_t}{1-u_t}$$

The second product ranges over terms *absent* from the document and therefore still depends on $d$. It is eliminated by the following identity, which converts it into a product over the whole vocabulary:

$$\prod_{t\,:\,x_t=1} \frac{p_t}{u_t} \;\cdot\; \prod_{t\,:\,x_t=0} \frac{1-p_t}{1-u_t} \;=\; \prod_{t\,:\,x_t=1} \frac{p_t\,(1-u_t)}{u_t\,(1-p_t)} \;\cdot\; \underbrace{\prod_{t} \frac{1-p_t}{1-u_t}}_{\text{independent of } d}$$

To verify the identity, expand its right-hand side. The final product over all $t$ splits into the terms present and the terms absent:

$$\prod_{t} \frac{1-p_t}{1-u_t} \;=\; \prod_{t\,:\,x_t=1} \frac{1-p_t}{1-u_t} \;\cdot\; \prod_{t\,:\,x_t=0} \frac{1-p_t}{1-u_t}$$

The first of these cancels exactly against the factor $(1-u_t)/(1-p_t)$ carried by each present term, leaving $\prod_{x_t=1} p_t/u_t$ and $\prod_{x_t=0} (1-p_t)/(1-u_t)$, which is the left-hand side. The residual product now ranges over the entire vocabulary independently of $d$, and is therefore constant for ranking.

**Assumption A3 (query terms only).** For terms not occurring in the query, relevance is assumed to carry no information about occurrence, so $p_t = u_t$ and the corresponding factors equal $1$. The product may therefore be restricted to $t \in q$.

Taking logarithms yields the **retrieval status value**, a sum of independent per-term weights:

$$\mathrm{RSV}(q, d) \;=\; \sum_{t \,\in\, q \,\cap\, d} c_t, \qquad\qquad c_t \;=\; \log \frac{p_t\,(1-u_t)}{u_t\,(1-p_t)}$$

The quantity $c_t$ is the **Robertson–Spärck Jones weight** (Robertson & Spärck Jones, 1976). Its form is a log odds ratio: the odds of observing term $t$ in a relevant document, divided by the odds of observing it in a non-relevant one. A term whose presence is equally likely under both conditions contributes $\log 1 = 0$. Written out in the four table entries of §4.2, the weight is

$$c_t \;=\; \log \frac{P(x_t = 1 \mid R=1)\;P(x_t = 0 \mid R=0)}{P(x_t = 1 \mid R=0)\;P(x_t = 0 \mid R=1)}$$

— the likelihood ratio when the term is present, divided by the likelihood ratio when it is absent. That reading is what makes an absent term contribute zero, and §5 reuses it with a count in place of presence.

The scoring function is now a sum over query terms of quantities that depend only on collection statistics for that term. This additive structure is what makes inverted-index retrieval possible; it is a consequence of A2, and every departure from term independence in a modern retriever sacrifices it.

#### 4.4 Estimation with relevance judgements

Suppose that relevance is known for the collection. The joint distribution of term occurrence and relevance is summarised by a contingency table, in which $N$ is the collection size, $R$ the number of relevant documents, $n_t$ the number containing term $t$, and $r_t$ the number that are both relevant and contain $t$:

| | contains $t$ | does not contain $t$ | total |
|---|---|---|---|
| relevant | $r_t$ | $R - r_t$ | $R$ |
| non-relevant | $n_t - r_t$ | $N - n_t - R + r_t$ | $N - R$ |
| total | $n_t$ | $N - n_t$ | $N$ |

Maximum likelihood estimates are $\hat{p}_t = r_t / R$ and $\hat{u}_t = (n_t - r_t)/(N - R)$. These are unusable when any cell is zero, which is common: a term occurring in every relevant document gives $\hat{p}_t = 1$ and an infinite weight. Adding $0.5$ to each cell — a standard smoothing correction — gives

$$c_t \;=\; \log \frac{(r_t + 0.5) \,/\, (R - r_t + 0.5)}{(n_t - r_t + 0.5) \,/\, (N - n_t - R + r_t + 0.5)}$$

This is the origin of the constants $0.5$ in the BM25 formula. They are not tuning parameters; they are a smoothing prior on a contingency table.

**Example.** Let $N = 1000$ and $n_t = 100$, and suppose 20 documents are known relevant, of which 15 contain $t$. The relevant odds are $15.5/5.5 = 2.818$ and the non-relevant odds $85.5/895.5 = 0.0955$, giving $c_t = \log(29.52) = 3.385$. The term is strong evidence of relevance: it occurs in three quarters of relevant documents but only a tenth of the collection.

#### 4.5 The case without relevance judgements

##### The collapse to IDF

In ordinary retrieval no relevance judgements exist. Setting $R = 0$ and $r_t = 0$ in the smoothed expression — that is, assuming nothing is known to be relevant — the relevant-odds factor becomes $0.5/0.5 = 1$ and the weight collapses to

$$c_t \;=\; \log \frac{N - n_t + 0.5}{n_t + 0.5}$$

This is inverse document frequency, obtained as a limiting case of a probabilistic weight rather than assumed. Two assumptions were made in that step, and it is worth separating them, since each is responsible for one factor of the weight.

**Assumption A4 (relevant documents negligible).** Relevant documents form a negligible fraction of the collection, so that the non-relevant document statistics may be approximated by the collection statistics: $u_t \approx n_t / N$. This is what turns the non-relevant odds $\hat u_t/(1-\hat u_t)$ into $(n_t + 0.5)/(N - n_t + 0.5)$.

**Assumption A5 (uninformative relevant-side estimate).** Nothing is known about $p_t$, and it is taken to be the same for every query term. Setting $R = r_t = 0$ in the smoothed table gives $\hat p_t = 0.5/1 = \tfrac12$, so the relevant odds $\hat p_t/(1-\hat p_t)$ equal $1$ for every term and drop out of the ranking (Croft & Harper, 1979). The choice of $\tfrac12$ is not innocent: a different constant $p$ would add $\log\frac{p}{1-p}$ to every query term's weight, and since the score sums over the query terms a document contains, that is a bonus proportional to the *number* of matched terms — a form of *coordination-level matching*, ranking by how many query terms a document contains, and it does change the ranking. Setting $p_t = \tfrac12$ makes the bonus zero, so that a term's weight depends on its rarity alone. Without A5 the weight would still carry the term-dependent factor $p_t(1-u_t)/\big(u_t(1-p_t)\big)$, and $p_t$ is exactly what cannot be estimated without relevance judgements.

Continuing the example above, the same term without relevance judgements receives $c_t = \log(900.5/100.5) = 2.193$, against $3.385$ with judgements. *Relevance feedback* — re-estimating $p_t$ from documents the user has marked relevant, exactly as in §4.4 — increases the weight of terms that are discriminative in the observed relevant set; adding such terms to the query is classical *query expansion*.

##### Relation to the classical $\log(N/n_t)$

The weight just derived is not the formula most readers will have met under the name IDF. The one they will have met is

$$\mathrm{IDF}_{\text{classical}}(t) \;=\; \log \frac{N}{n_t}$$

proposed by Karen Spärck Jones in 1972, some years before the probabilistic derivation above, and used for document scoring ever since: it is the IDF of tf–idf and of the classical vector space model, and it remains in use wherever tf–idf is. Spärck Jones's own argument was statistical — a term's *specificity* should decrease with the number of documents it occurs in — and the justification most often given today, information-theoretic in character, was supplied after the fact (Robertson, 2004). It runs as follows. Estimating the probability that a document drawn uniformly from the collection contains $t$ by $n_t/N$, the quantity

$$\log \frac{N}{n_t} \;=\; -\log \frac{n_t}{N}$$

is the *surprisal* of observing $t$ — how much information the observation carries. A term expected in one document in a thousand carries $\log 1000$; a term expected in every document carries $\log 1 = 0$; and a term is worth attending to exactly to the extent that its occurrence was unlikely. Two independent lines of reasoning, one about relevance and one about information, thus arrive at nearly the same function, which is why both survived.

##### The three forms compared

Three forms are now in play, and they are best compared together:

| | Form | Sign | Origin |
|---|---|---|---|
| classical | $\log\frac{N}{n_t}$ | $\geq 0$, zero at $n_t = N$ | Spärck Jones (1972); tf–idf |
| Robertson–Spärck Jones | $\log\frac{N - n_t + 0.5}{n_t + 0.5}$ | negative for $n_t > N/2$ | derived above |
| modified | $\ln\!\left(1 + \frac{N - n_t + 0.5}{n_t + 0.5}\right)$ | $> 0$ always | §6; used by this lesson and by Lucene |

Numerically, with $N = 1000$:

| $n_t$ | 1 | 10 | 100 | 300 | 500 | 900 |
|---|---|---|---|---|---|---|
| classical $\log\frac{N}{n_t}$ | 6.908 | 4.605 | 2.303 | 1.204 | 0.693 | 0.105 |
| Robertson–Spärck Jones | 6.502 | 4.547 | 2.193 | 0.846 | 0.000 | −2.193 |
| modified (§6) | 6.503 | 4.557 | 2.299 | 1.203 | 0.693 | 0.106 |

For $n_t \ll N$ all three agree closely, since the smoothing constants and the $-n_t$ correction are then negligible. They separate as $n_t$ grows, and the separation is not symmetric. The modified form and the classical form differ by exactly

$$\ln\!\left(1 + \tfrac{1}{N}\right) - \ln\!\left(1 + \tfrac{0.5}{n_t}\right),$$

which is at most $\max(1/N,\ 0.5/n_t)$ in magnitude — below $0.005$ from $n_t = 100$ onward at $N = 1000$, and vanishing as both grow — while the probabilistic form departs from both. The form used in practice is therefore, numerically, almost exactly Spärck Jones's original — the derivation of §4.1–§4.5 is best read as an explanation of *why* that formula works rather than as a replacement for it.

The probabilistic form crosses zero at $n_t = N/2$ and is negative beyond it. This is not an error: the model asserts that a term present in the majority of documents is, on balance, evidence *against* relevance. In ranking practice the behaviour is undesirable, and §7.3 describes the modification adopted by most implementations.

**Example on the running collection.** With $N = 4$ the collection is small enough that the asymptotic regime does not apply, and the difference between the forms is severe:

| term | $n_t$ | Robertson–Spärck Jones $\log\frac{N-n_t+0.5}{n_t+0.5}$ | modified $\ln\left(1 + \frac{N-n_t+0.5}{n_t+0.5}\right)$ |
|---|---|---|---|
| `the` | 3 | −0.8473 | 0.3567 |
| `cat` | 2 | 0.0000 | 0.6931 |
| `dog` | 2 | 0.0000 | 0.6931 |
| `mat` | 1 | 0.8473 | 1.2040 |

Under the probabilistic form, `cat` and `dog` — occurring in exactly half the collection — contribute nothing whatsoever, and `the` contributes negatively. Two things have gone wrong at once. The sign change is the $n_t \ge N/2$ behaviour just described, and it is a property of the formula at any $N$; the severity is a property of small $N$, where A4 fails outright — a single relevant document is a quarter of this collection, so $n_t/N$ is a poor estimate of $u_t$. The modified form of §6, used throughout the remainder of this lesson, preserves the ordering while keeping all weights positive: `mat` is worth 3.4 times as much evidence as `the`.

#### 4.6 Status of the assumptions

The derivation rests on five assumptions, each of which fails, or holds only approximately, in a specific and instructive way.

| | Assumption | Status | Consequence |
|---|---|---|---|
| A1 | binary document representation | false; counts are informative | addressed in §5 by the eliteness model, which reintroduces $f(t,d)$ |
| A2 | conditional independence of terms | false; `New York` is not `new` × `york` | retained regardless, because the resulting additivity is what permits indexed retrieval (§3, §10) |
| A3 | non-query terms uninformative | approximately true by construction | restricts the sum to query terms |
| A4 | relevant documents negligible in number | true for large collections | fails for small collections, as the $N = 4$ example above illustrates |
| A5 | $p_t$ constant across query terms | false; some query terms are far more characteristic of relevant documents than others | removes $p_t$ from the weight; relevance feedback (§4.4) is precisely the replacement of A5 by an estimate |

BM25 is best understood as this derivation plus two empirical repairs: A1 is relaxed by a fitted saturation curve (§5, §7.1), and document length — which the model ignores entirely — is introduced by a normalisation term whose justification is heuristic rather than probabilistic (§7.2). The function is therefore neither purely principled nor purely heuristic, and its two free parameters mark exactly the points at which theory was replaced by curve fitting.

### 5. Term frequency and the eliteness model

The binary independence model records only presence and absence. Incorporating term counts requires a model of how counts arise.

**The 2-Poisson model** (Harter, 1975; brought into the probabilistic framework by Robertson, van Rijsbergen & Porter, 1981) posits that, for each term $t$, a document is either *elite* for $t$ — genuinely about the concept the term names — or not, and that the number of occurrences $f$ of $t$ follows a Poisson distribution whose rate depends only on eliteness: rate $\lambda$ if elite, rate $\mu$ if not, with $\lambda > \mu$. Eliteness is not observed; it is a hidden binary variable $E$ that stands between relevance and the observed count. Relevance influences eliteness — write $\pi = P(E = 1 \mid R = 1)$ and $\pi' = P(E = 1 \mid R = 0)$, with $\pi > \pi'$ (the symbols $p_t, u_t$ of §4.2 are not reused, since they refer to term presence, not eliteness) — and eliteness influences the count.

**What the model predicts about the weight.** The weight of a term is defined exactly as in §4.3, with the count $f$ in place of the binary $x_t$: the likelihood ratio at the observed count, divided by the likelihood ratio at $f = 0$, so that an absent term contributes zero. The distribution of the count under each relevance state follows from the law of total probability over eliteness, together with the model's assumption that, given eliteness, the count does not depend on relevance:

$$w(f) \;=\; \log \frac{P(f \mid R=1)\;P(0 \mid R=0)}{P(f \mid R=0)\;P(0 \mid R=1)}, \qquad P(f \mid R) \;=\; P(E=1 \mid R)\,\frac{e^{-\lambda}\lambda^f}{f!} + P(E=0 \mid R)\,\frac{e^{-\mu}\mu^f}{f!}$$

Write $x = (\lambda/\mu)^f$, which increases from $1$ without bound as $f$ grows since $\lambda > \mu$, and $a = e^{-\lambda}$, $b = e^{-\mu}$. Cancelling the common $f!$ and $\mu^f$,

$$w(f) \;=\; \log \frac{\pi\,a\,x + (1-\pi)\,b}{\pi'\,a\,x + (1-\pi')\,b} \;+\; \log \frac{\pi'\,a + (1-\pi')\,b}{\pi\,a + (1-\pi)\,b}$$

The second term is a constant. The first is a ratio of two linear functions of $x$, and its derivative with respect to $x$ has the sign of $\pi\,a\,(1-\pi')\,b - \pi'\,a\,(1-\pi)\,b = ab\,(\pi - \pi')$, which is positive. So $w$ is strictly increasing in $f$; and as $x \to \infty$ the ratio tends to $\pi/\pi'$, so

$$\lim_{f \to \infty} w(f) \;=\; \log\frac{\pi\,\big(\pi'\,a + (1-\pi')\,b\big)}{\pi'\,\big(\pi\,a + (1-\pi)\,b\big)} \;<\; \infty$$

The model therefore predicts exactly the qualitative behaviour that §7.1 will exhibit for BM25: an absent term contributes zero, each further occurrence adds a positive but shrinking amount, and the total contribution of a term is bounded no matter how often it repeats. The first occurrence establishes that the document may be elite for the term; the twenty-first says almost nothing that the twentieth had not already said.

**Why the model is not used directly.** The weight $w(f)$ has four parameters per term — $\lambda, \mu, \pi, \pi'$ — none of which is observable, since eliteness is hidden. Robertson & Walker (1994) therefore replaced $w(f)$ by a closed-form function with the same three properties — zero at $f = 0$, increasing, bounded above — and only one free parameter, chosen so that the parameter controls how quickly the bound is approached: the function $f/(f + k_1)$, multiplied by the Robertson–Spärck Jones weight $c_t$ of §4.3 (which without relevance judgements is the IDF of §4.5). The scaling by $(k_1 + 1)$ seen in §6 does not change the shape; it makes a single occurrence in an average-length document score exactly the term weight (§7.1). The 1994 paper already corrected for document length, but in an all-or-nothing way — its variants BM11 and BM15 normalise fully and not at all; the version that interpolates between the two with the parameter $b$ of §7.2, presented at TREC-3 (Robertson et al., 1995), is what became BM25. The designation "BM" abbreviates *best match*; the numeral is a version label from that sequence of variants, not a count of anything.

The term-frequency component of BM25 is therefore a **fitted curve chosen to imitate the shape of a probabilistic model, not a quantity derived from one**. That is why $k_1$ has no closed form and must be set empirically: it stands in for the four unobservable parameters above.

### 6. The scoring function

$$s(q,d) \;=\; \sum_{t \in q} \mathrm{IDF}(t) \cdot \frac{f(t,d)\,(k_1 + 1)}{f(t,d) + k_1\left(1 - b + b\,\dfrac{|d|}{\mathrm{avgdl}}\right)}$$

$$\mathrm{IDF}(t) \;=\; \ln\left(1 + \frac{N - n_t + 0.5}{n_t + 0.5}\right)$$

The IDF term simplifies. Combining the argument of the logarithm over a common denominator, $n_t$ cancels in the numerator:

$$1 + \frac{N - n_t + 0.5}{n_t + 0.5} \;=\; \frac{(n_t + 0.5) + (N - n_t + 0.5)}{n_t + 0.5} \;=\; \frac{N + 1}{n_t + 0.5}$$

so that

$$\mathrm{IDF}(t) \;=\; \ln(N + 1) - \ln(n_t + 0.5)$$

Two properties follow immediately, and are used in §7.3 and §10:

- **Strict positivity.** $\mathrm{IDF}(t) > 0$ if and only if $n_t + 0.5 < N + 1$, that is $n_t < N + 0.5$, which holds for every term in every collection since $n_t \leq N$. No term can receive a negative weight.
- **Strict monotonicity.** Treating $n_t$ as continuous, $\dfrac{d\,\mathrm{IDF}}{d n_t} = -\dfrac{1}{n_t + 0.5} < 0$, so the weight decreases strictly with document frequency, and does so at a rate that itself diminishes as $n_t$ grows.

The second form is also the one to implement: one logarithm of a constant computed once for the collection, and one logarithm per distinct term.

| Symbol | Definition |
|---|---|
| $f(t,d)$ | occurrences of term $t$ in document $d$ |
| $n_t$ | number of documents containing $t$ |
| $N$ | collection size |
| $\lvert d \rvert$, $\mathrm{avgdl}$ | document length and mean document length, in tokens |
| $k_1$ | saturation rate; typical range 1.2–2.0 |
| $b$ | length normalisation strength, $b \in [0,1]$; typical value 0.75 |

The summation ranges over query term occurrences, so a term appearing twice in the query contributes twice. Some implementations deduplicate the query instead. The two conventions produce different rankings on repeated-term queries; either is defensible, but the choice must be documented and applied consistently.

### 7. Behaviour of the components

#### 7.1 Saturation

This section analyses how a document's score responds to $f(t,d)$, the number of times a query term occurs *within* that document, with everything else held fixed — the document's length, the term's weight, and both parameters. Only one summand of §6 and only one of its variables are in play, which makes this a question about a single-variable function. (Keep $f(t,d)$ distinct from $n_t$, the number of *documents* containing the term. Both are frequencies and both appear in the same formula, but they move independently and pull in opposite directions: a term is worth more when few documents contain it, and worth more when the document at hand contains it often.)

**Saturation** is the name for the behaviour that emerges. Each further occurrence of a term raises the score, but by less than the occurrence before it, and the total contribution of any one term is capped no matter how often it repeats. The intuition is informational, and it is the eliteness model of §5 restated: the first occurrence establishes that the document is *about* the term at all, which is the largest single fact available; the second confirms it; the twenty-first says almost nothing that was not already known after the twentieth. The numbers below make this exact — for a document of average length at $k_1 = 1.5$, the first occurrence alone supplies 40% of everything a term can contribute.

The alternative is worth stating, because it shows what the cap defends against. Were the contribution linear in $f$, a document repeating a query term five hundred times would outrank every genuinely relevant document in the collection, and the ranking would be trivial to manipulate and easily distorted even without manipulation. Boundedness is what makes the score robust to repetition.

Write the term-frequency component as a function of $f$ with the remaining quantities fixed:

$$g(f) \;=\; \frac{f\,(k_1 + 1)}{f + K}, \qquad K \;=\; k_1\left(1 - b + b\,\frac{|d|}{\mathrm{avgdl}}\right)$$

Then $g$ is increasing and concave on $f \geq 0$, with $g(0) = 0$ and

$$\lim_{f \to \infty} g(f) \;=\; k_1 + 1$$

A term's contribution is therefore bounded regardless of repetition. Concavity follows from $g''(f) = -2K(k_1+1)/(f+K)^3 < 0$ for $K > 0$.

**Example** ($k_1 = 1.5$, $b = 0.75$, document of average length so that $K = k_1 = 1.5$):

| $f$ | 1 | 2 | 3 | 5 | 10 | 100 | $\to \infty$ |
|---|---|---|---|---|---|---|---|
| $g(f)$ | 1.000 | 1.429 | 1.667 | 1.923 | 2.174 | 2.463 | 2.500 |

The first occurrence supplies $1/(1+K) = 40\%$ of the attainable contribution; occurrences beyond the tenth supply less than 14% in total.

Two limiting values of $k_1$ characterise the parameter:

- $k_1 = 0$ gives $K = 0$ and $g(f) = f/f = 1$ for all $f \geq 1$. BM25 degenerates to a sum of IDF weights over the terms present, discarding counts entirely.
- $k_1 \to \infty$ linearises $g$, removing saturation.

Thus $k_1$ interpolates between binary presence and unbounded term frequency. Small values suit short, homogeneous documents; larger values credit repetition more strongly.

#### 7.2 Length normalisation

The parameter $b$ scales $K$ by the document's relative length. At $b = 0$ the length term vanishes and $K = k_1$; at $b = 1$ the term frequency is normalised in full proportion to $|d|/\mathrm{avgdl}$.

**Example** ($f = 3$, $k_1 = 1.5$, $b = 0.75$, $\mathrm{avgdl} = 100$):

| $\lvert d \rvert$ | 50 | 100 | 400 |
|---|---|---|---|
| $g(f)$ | 1.905 | 1.667 | 0.952 |

Three occurrences in a 400-token document are worth half of three occurrences in a 50-token document.

The justification for a tunable $b$ is that document length has two distinct causes warranting opposite treatment. Under the **verbosity hypothesis**, a long document expresses the same content at greater length; its elevated term counts are artefacts and should be normalised away. Under the **scope hypothesis**, a long document covers more material; its terms are genuinely present and normalisation penalises it unjustly. Real collections mix both, and $b = 0.75$ is the empirical compromise.

#### 7.3 The two probabilistic IDF variants

Of the three forms tabulated in §4.5, two are the probabilistic form and its positivity-corrected modification, and they differ only in the additive $1$ inside the logarithm; this section records what that difference does to a ranking. The modification has no derivation, but it has a reading: by §6 it equals $\ln\frac{N+1}{n_t+0.5}$, which replaces the ratio *documents without $t$ : documents with $t$* by *all documents : documents with $t$* — that is, it is the classical $\log(N/n_t)$ with smoothing constants added — and its positivity is what makes the per-term upper bound of §10 valid as stated. Written as $\ln(N + 1) - \ln(n_t + 0.5)$, it vanishes only at $n_t = N + 0.5$ — outside the attainable range $n_t \in [1, N]$ — and is therefore positive throughout, whereas the Robertson–Spärck Jones form vanishes at $n_t = N/2$ and is negative beyond. Both are strictly decreasing in $n_t$, so they induce the same *ordering* of term weights; they differ in relative magnitudes, and only the modified form guarantees that a matched query term contributes a non-negative amount to a document's score.

**Example** ($N = 1000$, $n_t = 900$): the Robertson–Spärck Jones form yields $-2.193$; the modified form yields $+0.106$.

Most implementations — Lucene among them — adopt the modified form, since a term whose presence *lowers* a document's score destabilises ranking on small collections and on stopword-heavy queries. But not all do, and the two produce different scores and different rankings. Determine which form a library implements before comparing its output with another's.

### 8. A complete worked score

Query `cat mat`, parameters $k_1 = 1.5$, $b = 0.75$, running collection with $\mathrm{avgdl} = 7.25$.

The candidate set is $\mathrm{posting}(\texttt{cat}) \cup \mathrm{posting}(\texttt{mat}) = \{d_1, d_2\}$.

**Document $d_1$** ($|d| = 6$): the length factor is $1 - 0.75 + 0.75 \cdot \frac{6}{7.25} = 0.8707$, hence $K = 1.5 \times 0.8707 = 1.3060$.

| term | $f$ | $g(f) = \frac{2.5f}{f + 1.3060}$ | $\mathrm{IDF}$ | contribution |
|---|---|---|---|---|
| `cat` | 1 | 1.0841 | 0.6931 | 0.7514 |
| `mat` | 1 | 1.0841 | 1.2040 | 1.3052 |
| | | | **total** | **2.0567** |

The ranking is $d_1 > d_2$. Two effects separate them: $d_1$ contains the rarer term `mat`, and $d_1$ is shorter, so its single occurrence of `cat` receives a larger term-frequency component (1.0841 against 0.9555).

### 9. Variants

**BM25+** (Lv & Zhai, 2011a) adds a constant $\delta$ to the term-frequency component,

$$g_{+}(f) \;=\; \frac{f\,(k_1 + 1)}{f + K} + \delta,$$

correcting a genuine defect: under strong length normalisation the reward for containing a term approaches zero as $|d|$ grows.

**Example** ($f = 1$, $k_1 = 1.5$, $b = 0.75$, $\mathrm{avgdl} = 100$):

| $\lvert d \rvert$ | 100 | 500 | 2000 |
|---|---|---|---|
| $g(1)$ | 1.000 | 0.357 | 0.105 |

A 2000-token document containing the term once receives approximately one tenth the credit of an average-length document containing it once, and is thereby scarcely distinguished from a document not containing it at all. The additive $\delta$ establishes a floor on the reward for containment.

**BM25L** (Lv & Zhai, 2011b) addresses the same defect by shifting the normalised term frequency rather than adding a floor to the result.

**BM25F** (Robertson, Zaragoza & Taylor, 2004) extends the function to documents with fields — title, abstract, body — using per-field weights and per-field length normalisation. The weighting is applied to term frequencies *before* saturation, not to per-field scores afterwards. Scoring fields independently and summing produces a different and inferior function, because saturation is then applied per field rather than to the aggregate evidence.

**Lucene BM25** is the reference implementation underlying Elasticsearch and OpenSearch. It uses the $\ln(1 + \cdot)$ IDF and defaults to $k_1 = 1.2$ and $b = 0.75$. Two of its details matter when comparing scores with another implementation. First, since version 8 it omits the constant factor $(k_1 + 1)$ from the numerator of §6 — the ranking is unchanged, because every term's contribution is scaled by the same constant, but every score is smaller by that factor. Second, it stores each document's length in a single byte, so $\lvert d \rvert$ and hence $\mathrm{norm}[d]$ are quantised, which introduces small, systematic discrepancies against an exact implementation.

### 10. Efficient top-k retrieval

Two properties bound the cost of evaluating $s$. Only documents in the union of the query terms' posting lists can score above zero, so query cost scales with posting list length rather than collection size. Furthermore, the top $k$ can be obtained without scoring every candidate.

**WAND** (Broder et al., 2003) maintains an upper bound on each term's attainable contribution, obtained from the supremum of $g$ established in §7.1,

$$\mathrm{UB}(t) \;=\; \mathrm{IDF}(t) \cdot (k_1 + 1) \;\geq\; \max_{d} \; \mathrm{IDF}(t)\, g\big(f(t,d)\big),$$

together with a running threshold $\theta$ equal to the current $k$-th best score. A document $d$ whose accumulated bound over its matching terms satisfies $\sum_{t \in q \cap d} \mathrm{UB}(t) < \theta$ cannot enter the result set and is skipped without evaluation.

**Example.** For the running collection, $\mathrm{UB}(\texttt{cat}) = 0.6931 \times 2.5 = 1.733$ and $\mathrm{UB}(\texttt{mat}) = 1.2040 \times 2.5 = 3.010$. Suppose $k = 1$ and $d_1$ has been scored at $\theta = 2.0567$. A candidate matching `cat` alone has bound $1.733 < 2.0567$ and is provably unable to displace $d_1$; its score need never be computed. Only candidates matching `mat`, or both terms, require evaluation.

**Block-max WAND** (Ding & Suel, 2011) refines this by storing per-block maxima within posting lists, permitting skips at finer granularity.

These techniques are the reason a well-implemented term-based retriever answers queries over collections of $10^8$ documents in single-digit milliseconds on commodity CPUs. The skipping is possible only because the score is a sum of bounded per-term contributions over a *sparse* representation: most documents contain none of the query terms, and an upper bound on the rest is available in closed form. Retrieval methods that represent documents as dense vectors have no such structure — every document has a nonzero similarity to every query — and reach a comparable latency only by approximating the search.

### 11. Limitations

**Vocabulary mismatch.** The scoring function requires exact term identity after tokenisation. A query term `automobile` obtains no evidence from a document containing only `car`. Stemming conflates morphological variants (§13) but cannot bridge synonymy, and no amount of parameter tuning can: two distinct strings are two distinct dimensions of the representation, and their scores are computed independently.

**Term independence.** `New York` is scored as the independent contributions of `new` and `york`. Phrase and proximity extensions exist but are additions to the model rather than consequences of it.

**Absence of semantics.** Negation, sentiment, and paraphrase are not represented. A document asserting a proposition and one denying it receive nearly identical scores.

**Sensitivity to tokenisation.** Because $q$ and $d$ are tokeniser outputs, all of the above are properties of the tokeniser as much as of the scoring function. §13 quantifies this.

**The complementary method, and how to combine with it.** Vocabulary mismatch is the defect that motivates *embedding-based* retrieval, in which a learned function maps each document and each query to a vector in $\mathbb{R}^n$ and documents are ranked by proximity to the query vector — usually by *cosine similarity*, the cosine of the angle between the two vectors, $\mathbf{u}\cdot\mathbf{v}/(\lVert\mathbf{u}\rVert\,\lVert\mathbf{v}\rVert)$, where $\mathbf{u}\cdot\mathbf{v} = \sum_i u_i v_i$ is the dot product and $\lVert\mathbf{u}\rVert = \sqrt{\mathbf{u}\cdot\mathbf{u}}$ the length of a vector; it lies in $[-1, 1]$. Such a retriever matches paraphrases that share no term, and fails in the opposite regime to BM25: it has no reliable representation of a rare identifier such as `ORD-4417-B`, which BM25 handles perfectly because a term occurring in one document receives the maximal IDF weight. Because the two fail on disjoint inputs, combining them usually outperforms either.

The obstacle to combining them is §1(iii): BM25 scores are unbounded and depend on the query, while a cosine similarity lies in $[-1,1]$, so the two cannot be summed. **Reciprocal rank fusion** (Cormack, Clarke & Buettcher, 2009) avoids the problem by discarding the scores and retaining only positions. Given several rankings indexed by $i$, in which document $d$ occupies position $\mathrm{rank}_i(d)$ counting from 1,

$$\mathrm{RRF}(d) \;=\; \sum_{i} \frac{1}{\kappa + \mathrm{rank}_i(d)}, \qquad \kappa = 60 \text{ by convention}$$

Each ranking contributes a value that decreases with position and is bounded by $1/(\kappa+1)$, so no single ranking can dominate the sum; the constant $\kappa$ controls how sharply the top of a ranking is favoured. With $\kappa = 60$ a first place contributes $1/61 = 0.0164$ and a tenth place $1/70 = 0.0143$, a ratio of 1.15; with $\kappa = 0$ the same two positions differ by a factor of 10. Fusion requires no tuned weights and no calibration, which is exactly what makes it the appropriate default when the scales of the inputs are incomparable.

## Part II — Practice

### 12. The algorithm in full

Part I established the scoring function and its justification. This section states the complete procedure, separating the two phases that any retrieval system has: an offline phase that consumes the collection and produces an index, and an online phase that consumes a query and produces a ranking. Everything computable without knowing the query belongs in the first phase, because the second runs under a latency budget.

At the level of an interface, the algorithm consists of three functions: `build`, `score` and `search`. The type `Tokens` below is the multiset of the *Preliminaries* as it is represented in code — a list, because a list of strings carries the repetitions a set would discard.

```python
Tokens = list[str]

def build(corpus: list[Tokens]) -> Index: ...
def score(index: Index, q: Tokens, doc_id: int) -> float: ...
def search(index: Index, q: Tokens, k: int) -> list[tuple[int, float]]: ...
```

- **`build`** is the offline phase. It traverses the collection once and computes everything that does not depend on a query: the document frequency $n_t$ of each term and hence its weight, the term counts within each document, the document lengths and their mean, and the posting lists of §3. It runs once per collection, and its cost is amortised — spread — over every query thereafter.
- **`score`** evaluates $s(q,d)$ for a single query–document pair — the formula of §6, and nothing more. It is the definition of the ranking, the unit that is tested and the unit that is explained (§16).
- **`search`** is the online phase and the only function a caller needs. It determines which documents can score above zero, scores them, and returns the $k$ best in descending order — as `(doc_id, score)` pairs, that is, as document *identifiers* rather than documents.

The division is the offline/online boundary. In the steps that follow, `build` performs Steps 1–6, `search` Steps 8–12, and `score` is Step 10 for one document. Note that `score` is defined for every document while `search` must never invoke it on every document; Steps 9–10 and §10 close that gap.

#### 12.1 Phase 1 — index construction

**Input.** A collection of raw documents; a tokeniser $\mathrm{tok}$; the parameter $b$ (and $k_1$, if the optional Step 7 is performed).
**Output.** An index sufficient to score any query without revisiting the raw text.

**Step 0 — segmentation.** If documents exceed the granularity at which answers occur, split them first. For question-answering corpora the natural unit is the paragraph, and the identifiers assigned here are what `search` returns. Segmentation precedes everything, because $N$, $\mathrm{avgdl}$ and $n_t$ are all defined relative to the chosen unit: re-chunking a corpus changes every statistic in the index.

**Step 1 — tokenisation.** Apply $\mathrm{tok}$ to each unit, obtaining $\mathrm{tokens}[d]$. Record $\mathrm{tok}$ itself as part of the index; §13 explains why it must be reapplied identically at query time.

**Step 2 — accumulation.** Traverse the collection once, maintaining
- $\mathrm{tf}[d]$, a map from term to count within document $d$;
- $\mathrm{dl}[d] = \lvert \mathrm{tokens}[d] \rvert$, the document length;
- $\mathrm{df}[t]$, incremented once per document in which $t$ appears — once per *document*, not per occurrence, which is the classic over-count in a hand-written indexer.

**Step 3 — collection statistics.** Set $N$ to the number of units and

$$\mathrm{avgdl} \;=\; \frac{1}{N}\sum_{d} \mathrm{dl}[d]$$

**Step 4 — inverted index.** For each term $t$, build the posting list

$$\mathrm{post}[t] \;=\; \big[(d, \mathrm{tf}[d][t]) \;:\; \mathrm{tf}[d][t] > 0\big] \quad\text{sorted by } d$$

The order is required: merging posting lists in document order makes the union in Step 9 linear, and is a precondition for the skipping in Step 10. No sorting is actually needed to obtain it — if Step 2 traverses documents in identifier order, each posting list is appended to in that order and emerges sorted.

**Step 5 — term weights.** For each term, using the simplified form of §6,

$$\mathrm{idf}[t] \;=\; \ln(N+1) - \ln\big(\mathrm{df}[t] + 0.5\big)$$

**Step 6 — length factors.** For each document, precompute the quantity that appears in the scoring denominator,

$$\mathrm{norm}[d] \;=\; 1 - b + b\,\frac{\mathrm{dl}[d]}{\mathrm{avgdl}}$$

This depends on $b$ but not on the query or on $k_1$. Storing it converts three arithmetic operations per (term, document) pair at query time into one array lookup. Changing $b$ invalidates this array and nothing else.

**Step 7 — upper bounds (optional).** For each term, $\mathrm{UB}[t] = \mathrm{idf}[t] \cdot (k_1 + 1)$, as derived in §10. Required only if Step 10 uses skipping; depends on $k_1$, so changing $k_1$ invalidates this array and nothing else.

#### 12.2 Phase 2 — query evaluation

**Input.** A raw query string; the index (which already embodies $b$, Step 6); parameters $k_1$ and $k$.
**Output.** The $k$ highest-scoring document identifiers with their scores.

**Step 8 — query preparation.** Apply the *same* $\mathrm{tok}$ stored in Step 1, yielding $q = \mathrm{tok}(\text{query})$. Discard terms with no posting list: they are unrepresented in the collection and contribute zero. Do not discard duplicates unless the deduplication convention of §6 has been adopted.

**Step 9 — candidate generation.** The candidate set is

$$C \;=\; \bigcup_{t \in q} \{\,d : (d, \cdot) \in \mathrm{post}[t]\,\}$$

Documents outside $C$ contain no query term, score zero by construction, and are never examined. This is the step that decouples query cost from collection size.

**Step 10 — accumulation.** For each $d \in C$, compute

$$s(q,d) \;=\; \sum_{t \in q} \mathrm{idf}[t] \cdot \frac{f(t,d)\,(k_1+1)}{f(t,d) + k_1 \cdot \mathrm{norm}[d]}$$

Two traversal orders are possible and the choice has consequences:

- **Term-at-a-time (TAAT).** Process posting lists one after another, accumulating partial scores in a map from document to score. Simple; requires memory proportional to $\lvert C \rvert$; cannot skip, because no document's score is final until the last list has been processed.
- **Document-at-a-time (DAAT).** Advance all posting lists in parallel by document identifier, completing each document's score before moving on. Requires the sort from Step 4, uses memory proportional to the heap, and is the only order compatible with the WAND pruning of §10, since a document's score is finalised before the next is begun.

Production systems use DAAT. A teaching implementation may use TAAT, or the still simpler candidate-set evaluation shown in §14.

**Step 11 — selection.** Maintain a *min-heap* of size $k$ keyed by score — a container that returns its smallest element in constant time and admits insertion and removal of the smallest in $O(\log k)$ time. Push each completed document, and pop the smallest when the heap exceeds $k$; what remains is the $k$ best seen so far. Cost is $O(\lvert C \rvert \log k)$ rather than the $O(\lvert C \rvert \log \lvert C \rvert)$ of a full sort. Under DAAT the heap's minimum is exactly the threshold $\theta$ that WAND consumes.

**Step 12 — return.** Emit the heap contents in decreasing score order as $(d, s)$ pairs. Resolving identifiers to text is the caller's responsibility.

#### 12.3 Complexity

Let $T$ be the total token count of the collection, $V$ the vocabulary size, $P = \sum_t \lvert \mathrm{post}[t] \rvert$ the total number of postings, and $\lvert q \rvert$ the query length.

| Phase | Time | Space |
|---|---|---|
| Index construction (Steps 1–7) | $O(T)$ | $O(P + V + N)$ |
| Query evaluation (Steps 8–12) | $O\big(\sum_{t \in q} \lvert \mathrm{post}[t] \rvert + \lvert C \rvert \log k\big)$ | $O(\lvert C \rvert)$ TAAT, $O(k + \lvert q \rvert)$ DAAT |

Construction is linear in the collection: every token is examined once, and the posting lists emerge sorted by construction (Step 4), so no sort is required; an implementation that does sort them pays an additional $O(P \log N)$. The heap is touched once per candidate, not once per posting, hence the two terms. Query cost depends on the *lengths of the query terms' posting lists*, not on $N$ — which is why a rare term is cheap and why stopwords, whose posting lists approach length $N$, are expensive out of proportion to their contribution.

#### 12.4 Trace on the running example

Query `cat mat`, $k_1 = 1.5$, $b = 0.75$, $k = 2$.

| Step | Result |
|---|---|
| 3 | $N = 4$, $\mathrm{avgdl} = 7.25$ |
| 5 | $\mathrm{idf}[\texttt{cat}] = 0.6931$, $\mathrm{idf}[\texttt{mat}] = 1.2040$ |
| 6 | $\mathrm{norm}[d_1] = 0.8707$, $\mathrm{norm}[d_2] = 1.0776$ |
| 8 | $q = [\texttt{cat}, \texttt{mat}]$, both in vocabulary |
| 9 | $C = \{d_1, d_2\} \cup \{d_1\} = \{d_1, d_2\}$ — $d_3, d_4$ never touched |
| 10 | $s(q, d_1) = 2.0567$, $s(q, d_2) = 0.6623$ (§8) |
| 11–12 | $[(d_1, 2.0567), (d_2, 0.6623)]$ |

Half the collection is eliminated at Step 9 without arithmetic, on a collection of four documents. At $N = 10^6$ with a selective query the same step typically eliminates more than 99.9%.

### 13. Tokenisation

Tokenisation choices affect retrieval quality more than $k_1$ and $b$. Each is a modelling decision.

**Case folding.** Lowercasing is standard. The exception arises in collections where capitalisation distinguishes entities from common nouns and no named-entity recognition is available.

**Stopword removal.** Reduces posting list lengths and query latency at negligible cost in quality for most queries. It destroys queries whose content resides in function words, and interacts badly with phrase queries.

**Stemming.** Porter (1980) or Snowball stemming conflates morphological variants. In the running example, `dog` ($n_t = 2$) and `dogs` ($n_t = 1$) are distinct terms; a query for `dogs` retrieves only `d3`, while `dog` retrieves `d2` and `d4`. Under stemming all three are indexed as `dog`, and a single query retrieves all three documents. The gain is in recall; the cost is occasional conflation of unrelated terms, as Porter stemming maps both `university` and `universe` to `univers`.

**Numerals, punctuation and identifiers.** A tokeniser that splits `GPT-4` into `gpt` and `4` destroys precisely the rare, high-IDF signal on which term-based retrieval is strongest. Identifier handling should be verified explicitly on any corpus containing codes, versions or part numbers.

**Tokeniser symmetry.** Queries and documents must pass through an identical tokeniser. Asymmetry produces silent recall loss rather than an error.

```python
index = build([tok(d) for d in corpus])   # tok lowercases
search(index, "Cat".split(), k=4)         # -> [] : "Cat" is not a term in the index
search(index, tok("Cat"), k=4)            # -> [(d1, ...), (d2, ...)]
```

This is the most frequent defect in BM25 implementations and is not detected by any test that constructs its queries with the same helper used to build the index. Test it with a literal, unprocessed query string.

### 14. Implementation

At the scale of a few thousand passages, a direct implementation of §12 is adequate and more instructive than a library. The correspondence is one to one: `build` performs Steps 1–6, `search` performs Steps 8–12, and `score` is Step 10 for a single document. The parameter $b$ is fixed at build time, since it is baked into $\mathrm{norm}[d]$ (Step 6); only $k_1$ is a query-time argument.

```python
# Produced by Steps 1-6 of §12:
#   df[t]     number of documents containing t          (Step 2)
#   idf[t]    ln(N + 1) - ln(df[t] + 0.5)               (Step 5, simplified form of §6)
#   tf[d][t]  raw counts                                (Step 2)
#   dl[d]     document length;  avgdl = mean(dl)        (Steps 2-3)
#   norm[d]   1 - b + b * dl[d] / avgdl                 (Step 6; depends on b alone)
#   post[t]   [(d, count), ...] sorted by d             (Step 4)

import heapq

def score(index, q_tokens, doc_id, k1=1.5):
    K = k1 * index.norm[doc_id]                               # norm[d] already contains b
    return sum(
        index.idf[t] * (f * (k1 + 1)) / (f + K)
        for t in q_tokens
        if (f := index.tf[doc_id].get(t, 0)) > 0
    )

def search(index, q_tokens, k, k1=1.5):
    q = [t for t in q_tokens if t in index.post]              # Step 8
    cand = {d for t in q for d, _ in index.post[t]}           # Step 9
    scored = ((d, score(index, q, d, k1)) for d in cand)      # Step 10, per candidate         
    return heapq.nlargest(k, scored, key=lambda p: p[1])      # Steps 11-12
```

This is the simplest correct form: it materialises the candidate set from the posting lists, then completes each candidate's score in turn by looking counts up in `tf` — a forward map kept for convenience; the same counts sit in the posting lists (§3), and a merging implementation reads them there. It is neither of the two traversal orders of Step 10 as production systems implement them — it does not accumulate partial scores list by list (TAAT), and it does not advance the posting lists in parallel (DAAT) — and it is incapable of skipping, since it never sees documents in identifier order. The document-at-a-time merge is the prerequisite for §10's pruning.

Points of implementation:

- `idf` and `norm` depend only on the collection and on $b$. Computing them per query is the standard performance defect and is asymptotically equivalent to rebuilding the index on every request.
- Query terms absent from the vocabulary contribute zero and should be skipped rather than raising.
- `rank_bm25` is appropriate at this scale but scores every document for every query with no skipping. It is a pedagogical implementation. The correct successor is Lucene or Pyserini, not an optimised Python loop.

### 15. Parameter tuning

Sweep $k_1 \in \{0.9, 1.2, 1.5, 2.0\}$ and $b \in \{0.0, 0.3, 0.75, 1.0\}$ and measure recall@$k$ — the fraction of the known-relevant passages that appear among the $k$ returned, averaged over queries; the preamble to Part III defines it precisely, together with the splits and pool regimes it presupposes. The expected effect is a few points, substantially smaller than the effect of the tokenisation choices in §13.

Tuning is performed on the development split. Parameters selected on the test split invalidate the test split.

### 16. Score attribution

The scoring function is a sum over query terms, so any score decomposes exactly into per-term contributions. An implementation should expose this:

```python
explain(index, q_tokens, doc_id) -> list[tuple[str, float, int, float]]
```

returning, for each query term, its IDF, its frequency in the document, and its contribution. For $d_1$ under the query `cat mat`:

| term | $\mathrm{IDF}$ | $f$ | contribution |
|---|---|---|---|
| `mat` | 1.2040 | 1 | 1.3052 |
| `cat` | 0.6931 | 1 | 0.7514 |

Exact attribution of a ranking decision to individual terms has no analogue in embedding-based retrieval, where a cosine similarity of 0.83 between two vectors is a single number admitting no decomposition into causes. During error analysis this distinguishes three otherwise indistinguishable conditions: a term absent from the document ($f = 0$), a term present but insufficiently weighted (low IDF), and a term absent from the vocabulary owing to tokenisation.

## Part III — Exercises

The exercises assume a **labelled retrieval set**: a collection of questions, each paired with the identifiers of the passages that answer it. Those passages are the *gold* set $G_q$ for question $q$. Any such dataset will serve; question-answering corpora that ship supporting-paragraph labels are the convenient choice.

**Recall@$k$.** Let $R_q^{(k)}$ be the set of identifiers a retriever returns for query $q$ at cutoff $k$. Then

$$\mathrm{recall@}k \;=\; \frac{1}{|Q|}\sum_{q \in Q} \frac{\lvert R_q^{(k)} \cap G_q \rvert}{\lvert G_q \rvert}$$

the mean over the question set of the fraction of gold passages retrieved. It is the appropriate first-stage metric because a passage the retriever does not return cannot be recovered by anything downstream: recall@$k$ is a ceiling on the whole pipeline. It ignores the order within the top $k$; if ordering matters, report **mean reciprocal rank**, the mean over queries of $1/\mathrm{rank}$ of the first gold passage, which is $0$ when no gold passage appears.

**Two candidate-pool regimes.** The same retriever is evaluated under both, and the pair separates two distinct abilities:

- **Restricted pool** — retrieval among a small per-question candidate set, typically the question's own handful of passages. Isolates ranking quality from the difficulty of finding candidates at all.
- **Global pool** — a single index over every passage in the corpus. The realistic setting, and the one in which recall degrades as the pool grows.

**Splits.** Divide the labelled set into a development split and a test split. All parameter choices, tokenisation choices and error analysis are performed on the development split; the test split is measured once, at the end. A parameter selected by its test-split score has made the test split a second development split, and the resulting number no longer estimates performance on unseen queries.

Unless stated otherwise, work on the development split under the restricted pool.

1. **Implementation and validation.** Implement BM25 from the definition in §6. Verify the limiting cases of §7.1–§7.2 numerically: at $k_1 = 0$, documents containing the same term set receive identical scores irrespective of counts; at $b = 0$, scores are invariant to document length. Reproduce the worked example of §8 to four decimal places.

2. **Tokenisation ablation.** Measure recall@4 under four tokenisers: whitespace splitting; lowercasing; lowercasing with stopword removal; lowercasing with stopword removal and Porter stemming. Record the range of the results.

3. **Parameter sweep.** Grid over $k_1$ and $b$ as in §15. Compare the range of recall@4 to that obtained in Exercise 2, and state which factor dominates.

4. **Saturation.** Construct two documents: one containing the gold entity twenty times among unrelated content, one containing it twice within a directly relevant sentence. Predict the ranking from the saturation curve before measuring, then set $k_1 = 20$ and account for the change.

5. **Length normalisation.** Identify a query for which $b = 0$ and $b = 1$ disagree on the top-ranked document. Examine both documents and determine which behaviour is correct for this collection, with reference to the verbosity and scope hypotheses of §7.2.

6. **Scaling.** Re-run the best configuration against the global pool. Record the degradation in recall@$k$ as a function of pool size, sampling several intermediate sizes rather than only the two extremes.

7. **Attribution.** Implement `explain` as specified in §16. Apply it to the five worst retrieval failures from Exercise 6 and classify each as vocabulary mismatch, tokenisation failure, or query ambiguity.
